# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A canvas road editor with procedurally placed houses, offices, trees and traffic. The app has no runtime dependencies; `package.json` only holds dev tools (Prettier, Playwright, Vite). Run it with `npm run dev` (Vite's dev server, http://127.0.0.1:8080). The code is ES modules, which browsers won't load from `file://`, so `index.html` must be served (any static server works too).

**Build:** `npm run build` runs Vite (`vite.config.mjs`) and writes `dist/` (git-ignored) with one `index.html`, `app.css` and `app.js`; `npm run preview` serves it (the built page uses a module script, so it must be served, not opened from `file://`). Vite bundles the modules from `js/main.js` into one file and minifies it, which shortens their top-level names; nothing is global in the built page. `minifyHtml()` strips comments and whitespace between tags; Vite minifies the CSS. `tests/build.test.js` and `e2e/build.spec.js` cover the build (via `viteBuild()` in `tests/helpers/build.js`).

## Development process: TDD (always)

Every change, feature or bug fix, follows test-driven development:

1. **Red:** write a test that captures the change, as a unit test in `tests/<module>.test.js`, or an end-to-end test in `e2e/` for behaviour across the whole page. Run it and see it fail for the expected reason.
2. **Green:** write the minimum code that makes it pass.
3. **Refactor:** tidy up while the whole suite stays green: `npm test`, plus `npm run test:e2e` when the UI is involved.
4. Commit.

Don't write implementation code before a failing test exists for it. The only exception is a change that genuinely can't be tested, such as a pure visual tweak. Say so, and check it in the browser instead.

## Tests

Unit tests use Node's built-in runner, with no extra dependencies: `npm test` runs `node --test "tests/**/*.test.js"`. The modules expect a browser, so `tests/helpers/app.js` exports `loadApp()`, which follows `index.html`'s module graph and runs every module, in the order a browser evaluates them and with its `import`/`export` keywords stripped, in a fresh `vm` context with stand-ins for the DOM, canvas, `localStorage` and timers; `app.run('expr')` evaluates code inside it, where every module's top-level names are in scope (they are unique across modules, which this relies on), e.g. `app.run('game.paused')`. The animation loop never runs in tests (`requestAnimationFrame` is a no-op), so tests drive the app directly (e.g. `stepSim()`). Values made inside the app belong to its context, so pass them through `plain()` before strict deep-equality checks. Other helpers on the loaded app: `road(lanes, [x, y], ...)` builds roads directly (reusing points at the same spot, then `junctionize()`); `click(x, y)`, `rightClick(x, y)` and `canvasEvent(type, e)` drive the real canvas handlers; `windowEvent(type, e)` fires window listeners (keys); `elements[id]` are the fake DOM elements (buttons can be `.click()`ed); `storage` is the fake `localStorage`; `loadApp({ storage, quiet, sdk })` preloads a save, can silence expected warnings, and can install a stand-in CrazyGames SDK (see `tests/platform.test.js`; its `init()` is async, so `await` a tick before checking startup). Elements marked `hidden` in `index.html` start hidden. **End-to-end tests** use Playwright (`@playwright/test`): `npm run test:e2e` starts the Vite dev server on port 8091 and runs `e2e/*.spec.js` in the installed Chrome (`channel: "chrome"` in `playwright.config.js`, so no browser download is needed). Each test gets a fresh browser profile and fails if the page throws; it drives the page with the real mouse and keyboard and reads app state with `state(page, () => expr)`, which evaluates `expr` in the page with the exports of the modules in its `MODULES` list in scope (it imports them, getting the instances the app runs). `e2e/build.spec.js` builds `dist/` and serves it with Vite's `preview()` on port 8092. Traffic is rebuilt on the next animation frame after an edit, so wait for it with `expect.poll()` rather than reading it once. The first road of a fresh game triggers a toast at the bottom right, so don't click there. `e2e/app.spec.js` and `e2e/build.spec.js` block the CrazyGames SDK script (`page.route`), so they run offline against `localStorage`; `e2e/platform.spec.js` answers it with a stub SDK instead. There is one test file per module (`tests/<module>.test.js`); drawing-only modules (`render.js`, `scenery.js`, `terrain.js`) and startup (`main.js`) are covered by smoke tests at most.

## Files

`index.html` holds the markup and loads `style.css` and the scripts in `js/`. The scripts are ES modules: `index.html` loads `js/main.js`, the entry, which imports every other module (startup calls live there). Each module exports its top-level names and imports what it uses from the others. Imports are read-only, so values more than one module assigns live on the `game` object in `state.js` (`game.last`, `game.paused`, `game.traffic`, `game.selectedCar`, …); a value only its own module assigns stays an exported `let` (`roadsVersion`, `simTime`, `trafficLevel`), which importers see update live. Modules import each other in cycles, so top-level code may only call into a module that is already evaluated; calls from functions run later are fine. Keep top-level names unique across modules (the unit test harness relies on it).

## Architecture notes

- **CrazyGames SDK** (`platform.js`, https://docs.crazygames.com/sdk/intro/): `index.html` loads `crazygames-sdk-v3.js` before the app. `startPlatform()` awaits `SDK.init()` (which preloads the player's saved data), then loads the save between `loadingStart()` and `loadingStop()`; the start screen's buttons stay disabled until then. Saves (`load()`, `storeSave()`, a fresh game's delete) go through `saves`, which is the SDK's `data` module (same API as `localStorage`, kept with the player's account) when the SDK is usable, else `localStorage`. `setGameplay()` reports `gameplayStart()` when a game is entered and `gameplayStop()`/`gameplayStart()` as the settings pause and resume (via `setPaused()`), dropping repeats. With no SDK (other hosts, offline), environment `disabled`, or a failed `init()`, the game runs as before and SDK errors never break it. Locally (localhost/127.0.0.1) the SDK runs in its `local` environment. The game has no audio, so `muteAudio` needs nothing.
- The page is a single full-window `<canvas id="c">` over a green page background (matching `GRASS`); `render()` paints grass terrain over the whole visible area each frame.
- **Three coordinate spaces.** _World_ coordinates are what `points` are stored in. _Screen_ coordinates are CSS px relative to the canvas: screen = world × `view.scale` + (`view.x`, `view.y`). _Device_ pixels are the backing store, CSS size × `devicePixelRatio`, set by `resize()`. `render()` sets the world transform itself (`toWorld()`) and switches to identity for clearing and for compositing the preview `layer`. `pos(e)` gives the pointer in world coordinates, `screenPos(e)` in screen coordinates. `HIT`, `DRAG` and `CAR_PICK` are screen px (divide by `view.scale` to use them in world). `getImageData`/`putImageData` ignore the transform and work in device pixels.
- **Viewport:** the wheel zooms around the pointer, clamped to `MIN_ZOOM`–`MAX_ZOOM`. A left or middle press starts a `drag`; once the pointer has moved more than `DRAG` px it pans the view. A left press released without moving that far is a click. Holding W/A/S/D pans up/left/down/right at `PAN_SPEED` screen px/s (diagonals normalised; ignored with Ctrl/Alt/Meta): `input.js` tracks held keys and `panKeys(dt)`, called each frame from `main.js`, moves the view and re-targets the preview from `pointerScreen`. Reset leaves the view alone. Save stores the view along with the drawing, and `load()` restores it if present.
- **State:** `points` (world positions), `lines` (`[a, b, lanes]`: indices into `points` and lanes each way, 1 for a 2-lane road or 2 for a 4-lane road; saves without `lanes` load as 4-lane), `roadLanes` (type for new roads), `last` (index of the most recently clicked point) and `pointer` (current pointer position, `null` when outside the canvas).
- **Clicking** (`pointerup` after a left press that didn't drag; pointer events, so mouse, pen and touch all work): if the click is within `HIT` px of an existing point, that point is reused; otherwise a new point is added. Either way a solid line is added from `last` to it (skipping self-lines and duplicates) and it becomes `last`.
- **Angle snapping:** `target()` decides where a click or the preview lands, for clicks, `pointermove` and wheel zoom. An existing point within `HIT` wins. Otherwise, when `snap` is on and there is a `last` point, the position is moved onto the horizontal or vertical through `last` if the road from `last` is within `SNAP_ANGLE` degrees of it; otherwise it is left alone. The snapped position is hit-tested again, so it reuses a point it lands near instead of stacking a new point (and a duplicate road) on top of it. The Snap button toggles `snap` (on by default, not saved).
- **Preview:** while the pointer is over the canvas, a half-opacity road runs from `last` to the pointer. It is drawn opaque on the offscreen `layer` canvas (kept the same size as the main canvas by `resize()`), then copied onto the main canvas with `globalAlpha = 0.5`, so its stacked layers don't show through each other. Within `HIT` px of a point, the pointer snaps to that point's exact position, using the same `hitTest()` as clicking.
- **Right click** (`pointerdown` with `button === 2`) on a point (by `hitTest()`) asks for confirmation with `confirm()`, then calls `remove()`, which deletes the point and its lines and shifts higher indices in `lines` and `last` down by one; removing `last` ends the chain. Right click elsewhere sets `last = null`, ending the chain and hiding the preview, and opens the road type menu (`#road-menu`, `openMenu()`) at the cursor; choosing 2-lane or 4-lane sets `roadLanes` for roads drawn afterwards. The wheel or Escape closes the menu, and so does a left or middle press on the canvas, which then does nothing else (no point, no drag); a right click closes it and acts as usual. After either, `prune()` removes every point with no roads except `last` (a new chain's first point has none until the next click), so ending a chain on a lone point, or deleting a point that strands a neighbour, leaves no stray points. The canvas's context menu is disabled.
- **Controls** are fixed at the top-right, over the canvas, as bare icons (no background or border): a speed button (`#speed`: ❯ normal, ❯❯ 2×, ❯❯❯ 3× chevrons; each click cycles `simSpeed`, and `frame()` runs `stepSim()` that many times per frame, so the rules stay exactly as accurate; not saved) and a ⚙ gear (`#settings`) that opens the settings popup (`#settings-menu`): a full-screen blurred backdrop with glossy green game-style buttons stacked in the middle (Snap, Save, Reset, Resume). Opening it pauses the simulation (`openSettings()`), and closing it (Resume, Escape, Reset, or a click on the backdrop) restores the previous paused state (`closeSettings()`). The backdrop covers the canvas, so no canvas click happens while it's open. A round `?` at the top left (`#help`) opens the help popup (`#help-menu`, same backdrop) listing the game controls, with a Resume button (`#help-close`); it pauses and restores the same way. Both popups come from `pausingOverlay()` in `input.js`. The favicon is a 🛣️ emoji in an inline SVG data URL. Reset clears `points`, `lines` and `last` but leaves the view and the saved copy alone. Save writes `{ points, lines, last, view, lights }` as JSON to `localStorage` under `STORAGE_KEY`; `load()` restores it on startup. Saving is manual only.
- **Lines are drawn as roads** by `roads(c, segs)`, which draws `[p, q, lanes]` segments on context `c`, each `roadWidth(lanes)` wide: a grey kerb, dark asphalt, thin white edge lines, a double solid yellow line between the two directions and, on 4-lane roads, dashed white lines between the lanes on each side (`LANE_W` wide). `ROAD_WIDTH` is the widest road's width, used where a clearance can't depend on one road (e.g. at points). `chains()` first joins segments into runs through points where exactly two roads of the same type meet, so corners, bends and straight joins draw as one continuous road (one polyline per pass); chains end at junctions, dead ends and type changes, and a loop is a closed chain. Each chain's bends are then rounded (`filletPath()`: the corner becomes a curve from `bendTangent()` before it to the same after, giving the inner kerb a radius of `INNER_R`), so both edges and the markings curve. Markings are the chain's center line, cut short at each chain end by half the widest road meeting there (`cutPath()`), then shifted sideways (`offsetPath()`: mitred corners, bevelled on the outside of turns sharper than a right angle so they stay on the road). Each layer is drawn for every chain before the next layer starts, so roads meeting at a point merge into clean junctions.
- **Junctions:** roads never cross without sharing a point. After every click, `junctionize()` splits any two roads that cross mid-way at a new shared point (and any road running through another road's point), so markings stop at the junction and cars can turn there; `load()` runs it too, for older saves. Clicking on a road (within its asphalt, away from its ends) joins the new road onto it: `target()` uses `roadAt()` to find the join (where the angle-snap axis meets the road's center line, or the nearest point on it) and returns `split`, the line to split at the new point.
- **Boxes along roads** are generated by `layout()`, not stored or saved. On both sides of each road it places boxes `BOX_MIN`–2×`BOX_MIN` wide with `BOX_GAP` between them, set back from that road's own width, starting `ROAD_WIDTH` from each end, and skips any box that would come near a road, a point or an already placed box. Sizes come from a PRNG (`rng()`) seeded with the road's endpoint coordinates, so the layout is stable. After all boxes are placed, `layout()` puts a tree (`tree()`: round canopy with a highlight and shadow) in the `BOX_GAP` after each placed box, if it is clear of roads, points, boxes and other trees; trees never displace boxes. `layout()` returns `{ boxes, trees }`, and `getScene()` caches it, keyed on `roadsVersion` (bumped by `roadsChanged()`, which every change to `points` or `lines` must call) plus their lengths as a safety net. `house()` draws each box as a top-down house: a drop shadow, a hip roof with four faces shaded against `LIGHT`, and sometimes a chimney. Roof colour (from `ROOFS`) and chimney come from a PRNG seeded with the box's center, kept separate from the layout PRNG so they don't change box sizes.
- **Offices:** `layout()` marks about `OFFICE_SHARE` of boxes as `office`, chosen by a PRNG seeded from position, with at least one office whenever there are two or more boxes. `office()` draws them as flat roofs with a parapet and rooftop units; the other boxes are houses. Each box also records `seg` (index into `lines` of the road it fronts) and `along` (distance along that line from its first point).
- **Traffic:** `makeTraffic()` builds the road graph (`adj`: points are nodes, lines are edges) and its connected components (`comp`), and gives houses that can reach an office `CARS_PER_HOUSE` cars each (up to `MAX_CARS`). A car drives from its building's door along the shortest route (`route()`: Dijkstra seeded with distances from the building to both ends of its line), stays in a building for a moment, then heads home if it was at an office, or to a random reachable office if it was at home. Each trip picks a random lane on the car's side, clamped to each road's lanes; its path is the center line shifted `(lane + 0.5) × LANE_W` sideways, to the right or left depending on `KEEP`; `curveTurns()` then replaces each turn's sharp corner with a quadratic curve through the point where the two lanes meet, split into `CURVE_STEPS` turn pieces; the road piece before ends early (its `tail` is how far before the lane's end) and the one after starts later (its `start` grows), so lane positions stay true. At a junction the curve starts after the stop line. At a bend between two roads of the same type, the car's curve is the road's own rounded center line (same `bendTangent()`) shifted sideways into its lane, so it stays exactly centered. Straight-on joins and driveways aren't curved. Code that needs the lane after a turn uses `nextRoad()` rather than assuming a single turn piece. `route()` also returns a speed multiplier per path piece (`ROAD_SPEED`: 4-lane roads 1.5×, 2-lane roads, driveways and turns 1×) and `pieces`, what each path piece is: a driveway, a stretch of a lane (`key` from `laneKey(line, dir, lane)`, and `start`, how far along the lane it begins), or a turn at a point. Cars can only turn where roads share a point.
- **Simulation** (`sim.js`, `stepSim()` each frame unless paused): cars are indexed per lane by lane position (`laneSpot()`; a car on a turn, or pulling out of a driveway, counts on the lane it's entering). Each car's furthest allowed position (`limit`, with the reason in `car.limitBy` and the blocking car in `car.leader`) comes from the car ahead (or the first car within `LOOKAHEAD` on the next lane), a junction stop line, or waiting at the door until the lane has room. Speed is capped by gap / `HEADWAY`, changes by at most `ACCEL`/`DECEL`, and never passes the limit, so cars never overlap. A junction (3+ roads, from `makeJunctions()`) has a box of radius `clear`; a car stops at `clear` before the point until `canEnter()` lets it in. It asks from comfortable braking distance (so a car that may go keeps its speed), and only if it's the front car of its lane or the car ahead is already going through, so a queued car never holds the box. To get in, its exit lane must have room (or the car in the way still be moving, which is how stranded box-blockers and gridlock arise) with no other car in the box heading there, then a traffic light decides (green, or amber when too close to stop at `DECEL_COMFORT`), or without one it gives way to crossing approaches (`compatible()`: same road and direction, or straight opposite) already in the box or arrived first. A junction is `blocked` after `BLOCK_TIME` s and `gridlock` after `GRIDLOCK_TIME` s of total standstill (no car in its box, or waiting at it while free to go, has moved; cars held at a red or amber light don't count). `render()` draws red queue bands under runs of stopped cars (`drawQueues()`), pulsing amber/red rings with a "!" on blocked/gridlocked junctions (`drawJunctionAlerts()`), and `updateAlerts()` (each frame from `main.js`) shows a toast at the bottom right (`#toasts`, `showGridlockToast()` in `inspect.js`) each time a junction becomes gridlocked (`notified` stops repeats until it clears). Toasts stack one below another and fade after `TOAST_TIME`; clicking one removes it and centres the view on its junction (`centerOn()`), keeping the zoom. Cars show brake lights from `car.braking`.
- **Traffic lights** (`lights.js`): `lights` maps a junction's position (`posKey()`, so it survives point renumbering) to `{ green, start }`. Each junction's approaches are grouped into phases by axis (`junctionPhases()`, stored on the junction as `phases`), and a signal cycles through them: `green` s, then `AMBER`, then `ALL_RED`. `drawLights()` draws a signal head on the kerb at each approach's stop line and a red/amber stop bar across its lanes when it isn't green. Signals whose junction disappears are dropped in `getScene()`. Save stores them as `[posKey, green]` pairs and `load()` restores them; Reset clears them.
- **Traffic level:** − and + buttons beside the mode buttons (`#traffic-less`, `#traffic-more`) call `adjustTraffic()`, which uses `changeTraffic()` to step `trafficLevel` by `TRAFFIC_STEP` (10% of normal) between `TRAFFIC_MIN` and `TRAFFIC_MAX`, and shows a toast. The car count is `t.baseCount` (the normal number for the map) × `trafficLevel`: new cars start parked at random homes (`newCar()`), and removals take parked cars first. `makeTraffic()` applies the level, so it carries over when the roads change. Toasts come from `showToast(title, sub, kind, onClick)` in `inspect.js` (`'alert'` red for gridlock, `'info'` dark).
- **Modes:** two buttons at the bottom centre (`#mode-road` 🛣️, `#mode-traffic` 🚦) set `mode` via `setMode()`, which also ends any road being drawn and clears selections (`clearSelection()`). In Road mode clicks build roads as described above (paused or not). In Traffic mode clicks never build; a left click (`pointerup`), paused or running, in priority order: a car selects it (route shown); a junction point (via `hitTest()`) toggles its signal (none ↔ timed) and selects it (`selectedJunction`, light blue ring and the bottom-left panel with phase, countdown, green-time slider, waiting count, status and an add/remove button); a road (`roadUnder()`) selects it (`selectedRoad`); a building selects it; anywhere else just deselects. Right click only deselects (no point removal, no road type menu). The cursor turns to a hand over anything clickable. Route lines and the selected building's outline are drawn in Traffic mode. The panel's × closes it.
- **Road flow:** each frame `stepSim()` logs in `t.flow` (by `'line:dir'`, see `roadDir()`) the time each car leaves a road. `roadStats(t, line, dir)` gives live figures for one direction: cars, stopped, average speed as a share of free speed, flow per minute over `FLOW_WINDOW` s, longest queue in px, average wait, and a level (Free / Busy / Congested / Jammed by speed). For the selected road, `drawRoadFlow()` outlines it in light blue and tints each direction's lanes by level (`LEVEL_COLORS`), and the road panel shows the figures in a column per direction (named by compass `heading()`). `getScene()` rebuilds traffic whenever the roads change. Car motion uses `Math.random()`, so unlike the layout it isn't repeatable.
- **Animation:** a `requestAnimationFrame` loop (`frame()`) moves the cars (`stepSim()`, with `dt` capped at 0.1 s) and calls `render()` every frame. `paused` (not saved) is only set while the settings menu is open; there is no Play/Pause button. While paused, cars and their wait timers are frozen but the loop keeps rendering, so editing, panning and zooming still work. Editing roads while paused still rebuilds traffic. Car selection (`carAt()`, within `CAR_PICK` screen px) and building selection (`boxAt()`) happen in Traffic mode (see Modes). `shownCars()` gives the selected car, or every driving car whose `to` is the selected box, and `render()` draws each one's remaining path (`path` from `pieceAt()` on) as a light blue line ending in a dot at the destination door, a ring around each, and the selected box's outline. Traffic rebuilds clear all selections.
- **Rendering is immediate-mode:** `render()` clears and redraws everything (terrain, offices and houses, then trees, then roads, then route lines, then cars via `drawCars()`, then preview) from state. Points themselves are not drawn; they only exist for snapping, joining roads and right-click removal. It runs every animation frame, on every pointer event and after `resize()`, which is needed because setting `width`/`height` clears the canvas. New visuals should be added to `render()` rather than drawn directly.
