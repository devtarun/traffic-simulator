# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A canvas road editor with procedurally placed houses, offices, trees and traffic. There is no build step, package manager, linter, or test suite, and no external dependencies. Run it by opening `index.html` in a browser (or serving the folder with any static server, e.g. `npx serve .` or `python -m http.server`).

## Files

`index.html` holds the markup and loads `style.css` and the scripts in `js/`. The scripts are plain `<script src>` tags sharing one global scope, not ES modules, so the page still works opened straight from disk (Chrome blocks modules over `file://`). Top-level `const`/`let`/functions in one file are visible to the others. Load order matters, because top-level code runs as each file loads: anything a file runs immediately must be defined by an earlier file. Startup calls live in `main.js`, which is last.

| File | Contents |
|---|---|
| `js/state.js` | Constants/settings, shared state (`points`, `lines`, `last`, `pointer`, `snap`, `view`, `drag`), `screenPos()`, `pos()`, `hitTest()` |
| `js/geometry.js` | `rng()`, `hash()`, oriented-box helpers (`local`, `corners`, `segBoxDist`, `boxesOverlap`), `pointSegDist()` |
| `js/roads.js` | `line()`, `roads()` |
| `js/layout.js` | `layout()` (boxes, offices, trees), `getScene()` cache |
| `js/scenery.js` | `house()`, `office()`, `tree()` drawing |
| `js/traffic.js` | Road graph, `route()`, cars (`makeTraffic`, `depart`, `stepCar`, `carPos`) |
| `js/render.js` | Preview `layer`, `render()`, `resize()` |

| `js/main.js` | Startup (`load()`, `resize()`) and the animation loop; must load last |

## Architecture notes

- The page is a single full-window `<canvas id="c">` on a white page background; the canvas itself is transparent.
- **Three coordinate spaces.** *World* coordinates are what `points` are stored in. *Screen* coordinates are CSS px relative to the canvas: screen = world × `view.scale` + (`view.x`, `view.y`). *Device* pixels are the backing store, CSS size × `devicePixelRatio`, set by `resize()`. `render()` sets the world transform itself (`toWorld()`) and switches to identity for clearing and for compositing the preview `layer`. `pos(e)` gives the pointer in world coordinates, `screenPos(e)` in screen coordinates. `HIT`, `DRAG` and point `RADIUS` are screen px (divide by `view.scale` to use them in world). `getImageData`/`putImageData` ignore the transform and work in device pixels.
- **Viewport:** the wheel zooms around the pointer, clamped to `MIN_ZOOM`–`MAX_ZOOM`. A left or middle press starts a `drag`; once the pointer has moved more than `DRAG` px it pans the view. A left press released without moving that far is a click. Holding W/A/S/D pans up/left/down/right at `PAN_SPEED` screen px/s (diagonals normalised; ignored with Ctrl/Alt/Meta): `input.js` tracks held keys and `panKeys(dt)`, called each frame from `main.js`, moves the view and re-targets the preview from `pointerScreen`. Reset leaves the view alone. Save stores the view along with the drawing, and `load()` restores it if present.
- **State:** `points` (world positions), `lines` (`[a, b, lanes]`: indices into `points` and lanes each way, 1 for a 2-lane road or 2 for a 4-lane road; saves without `lanes` load as 4-lane), `roadLanes` (type for new roads), `last` (index of the most recently clicked point) and `pointer` (current pointer position, `null` when outside the canvas).
- **Clicking** (`pointerup` after a left press that didn't drag; pointer events, so mouse, pen and touch all work): if the click is within `HIT` px of an existing point, that point is reused; otherwise a new point is added. Either way a solid line is added from `last` to it (skipping self-lines and duplicates) and it becomes `last`.
- **Angle snapping:** `target()` decides where a click or the preview lands, for clicks, `pointermove` and wheel zoom. An existing point within `HIT` wins. Otherwise, when `snap` is on and there is a `last` point, the position is moved onto the horizontal or vertical through `last` if the road from `last` is within `SNAP_ANGLE` degrees of it; otherwise it is left alone. The snapped position is hit-tested again, so it reuses a point it lands near instead of stacking a new point (and a duplicate road) on top of it. The Snap button toggles `snap` (on by default, not saved).
- **Preview:** while the pointer is over the canvas, a half-opacity road runs from `last` to the pointer. It is drawn opaque on the offscreen `layer` canvas (kept the same size as the main canvas by `resize()`), then copied onto the main canvas with `globalAlpha = 0.5`, so its stacked layers don't show through each other. Within `HIT` px of a point, the pointer snaps to that point's exact position, using the same `hitTest()` as clicking.
- **Right click** (`pointerdown` with `button === 2`) on a point (by `hitTest()`) asks for confirmation with `confirm()`, then calls `remove()`, which deletes the point and its lines and shifts higher indices in `lines` and `last` down by one; removing `last` ends the chain. Right click elsewhere sets `last = null`, ending the chain and hiding the preview, and opens the road type menu (`#road-menu`, `openMenu()`) at the cursor; choosing 2-lane or 4-lane sets `roadLanes` for roads drawn afterwards. The wheel or Escape closes the menu, and so does a left or middle press on the canvas, which then does nothing else (no point, no drag); a right click closes it and acts as usual. After either, `prune()` removes every point with no roads except `last` (a new chain's first point has none until the next click), so ending a chain on a lone point, or deleting a point that strands a neighbour, leaves no stray points. The canvas's context menu is disabled.
- **Controls** are fixed at the top-right, over the canvas. Reset clears `points`, `lines` and `last` but leaves the view and the saved copy alone. Save writes `{ points, lines, last, view }` as JSON to `localStorage` under `STORAGE_KEY`; `load()` restores it on startup. Saving is manual only.
- **Lines are drawn as roads** by `roads(c, segs)`, which draws `[p, q, lanes]` segments on context `c`, each `roadWidth(lanes)` wide: asphalt, white edge lines, a double solid yellow line between the two directions and, on 4-lane roads, dashed white lines between the lanes on each side (`LANE_W` wide). `ROAD_WIDTH` is the widest road's width, used where a clearance can't depend on one road (e.g. at points). Markings are the center line shifted sideways and stop half a road-width short of each end to keep junctions clear. Each layer is drawn for every line before the next layer starts, so roads that cross merge into junctions.
- **Boxes along roads** are generated by `layout()`, not stored or saved. On both sides of each road it places boxes `BOX_MIN`–2×`BOX_MIN` wide with `BOX_GAP` between them, set back from that road's own width, starting `ROAD_WIDTH` from each end, and skips any box that would come near a road, a point or an already placed box. Sizes come from a PRNG (`rng()`) seeded with the road's endpoint coordinates, so the layout is stable. After all boxes are placed, `layout()` puts a tree (`tree()`: round canopy with a highlight and shadow) in the `BOX_GAP` after each placed box, if it is clear of roads, points, boxes and other trees; trees never displace boxes. `layout()` returns `{ boxes, trees }`, and `getScene()` caches it, keyed on `points` and `lines`. `house()` draws each box as a top-down house: a drop shadow, a hip roof with four faces shaded against `LIGHT`, and sometimes a chimney. Roof colour (from `ROOFS`) and chimney come from a PRNG seeded with the box's center, kept separate from the layout PRNG so they don't change box sizes.
- **Offices:** `layout()` marks about `OFFICE_SHARE` of boxes as `office`, chosen by a PRNG seeded from position, with at least one office whenever there are two or more boxes. `office()` draws them as flat roofs with a parapet and rooftop units; the other boxes are houses. Each box also records `seg` (index into `lines` of the road it fronts) and `along` (distance along that line from its first point).
- **Traffic:** `makeTraffic()` builds the road graph (`adj`: points are nodes, lines are edges) and its connected components (`comp`), and gives houses that can reach an office `CARS_PER_HOUSE` cars each (up to `MAX_CARS`). A car drives from its building's door along the shortest route (`route()`: Dijkstra seeded with distances from the building to both ends of its line), stays in a building for a moment, then heads home if it was at an office, or to a random reachable office if it was at home. Each trip picks a random lane on the car's side, clamped to each road's lanes; its path is the center line shifted `(lane + 0.5) × LANE_W` sideways, to the right or left depending on `KEEP`; the short joins between shifted pieces are the turns. `route()` also returns a speed multiplier per path piece (`ROAD_SPEED`: 4-lane roads 1.5×, 2-lane roads, driveways and turns 1×), which `stepCar()` applies via `pieceAt()`. Cars can only turn where roads share a point. `getScene()` rebuilds traffic whenever the roads change. Car motion uses `Math.random()`, so unlike the layout it isn't repeatable.
- **Animation:** a `requestAnimationFrame` loop (`frame()`) moves the cars (`stepCar()`, with `dt` capped at 0.1 s) and calls `render()` every frame.
- **Rendering is immediate-mode:** `render()` clears and redraws everything (offices and houses, then trees, then roads, then moving cars, then preview, then points on top) from state. It runs every animation frame, on every pointer event and after `resize()`, which is needed because setting `width`/`height` clears the canvas. New visuals should be added to `render()` rather than drawn directly.
