# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A single-file blank canvas: everything (markup, CSS, JS) lives in `index.html`. There is no build step, package manager, linter, or test suite, and no external dependencies. Run it by opening `index.html` in a browser (or serving the folder with any static server, e.g. `npx serve .` or `python -m http.server`).

## Architecture notes

- The page is a single full-window `<canvas id="c">` on a white page background; the canvas itself is transparent.
- **Three coordinate spaces.** *World* coordinates are what `points` are stored in. *Screen* coordinates are CSS px relative to the canvas: screen = world × `view.scale` + (`view.x`, `view.y`). *Device* pixels are the backing store, CSS size × `devicePixelRatio`, set by `resize()`. `render()` sets the world transform itself (`toWorld()`) and switches to identity for clearing and for compositing the preview `layer`. `pos(e)` gives the pointer in world coordinates, `screenPos(e)` in screen coordinates. `HIT`, `DRAG` and point `RADIUS` are screen px (divide by `view.scale` to use them in world). `getImageData`/`putImageData` ignore the transform and work in device pixels.
- **Viewport:** the wheel zooms around the pointer, clamped to `MIN_ZOOM`–`MAX_ZOOM`. A left or middle press starts a `drag`; once the pointer has moved more than `DRAG` px it pans the view. A left press released without moving that far is a click. Reset leaves the view alone. Save stores the view along with the drawing, and `load()` restores it if present.
- **State:** `points` (world positions), `lines` (pairs of indices into `points`), `last` (index of the most recently clicked point) and `pointer` (current pointer position, `null` when outside the canvas).
- **Clicking** (`pointerup` after a left press that didn't drag; pointer events, so mouse, pen and touch all work): if the click is within `HIT` px of an existing point, that point is reused; otherwise a new point is added. Either way a solid line is added from `last` to it (skipping self-lines and duplicates) and it becomes `last`.
- **Angle snapping:** `target()` decides where a click or the preview lands, for clicks, `pointermove` and wheel zoom. An existing point within `HIT` wins. Otherwise, when `snap` is on and there is a `last` point, the position is moved onto the horizontal or vertical through `last` if the road from `last` is within `SNAP_ANGLE` degrees of it; otherwise it is left alone. The snapped position is hit-tested again, so it reuses a point it lands near instead of stacking a new point (and a duplicate road) on top of it. The Snap button toggles `snap` (on by default, not saved).
- **Preview:** while the pointer is over the canvas, a half-opacity road runs from `last` to the pointer. It is drawn opaque on the offscreen `layer` canvas (kept the same size as the main canvas by `resize()`), then copied onto the main canvas with `globalAlpha = 0.5`, so its stacked layers don't show through each other. Within `HIT` px of a point, the pointer snaps to that point's exact position, using the same `hitTest()` as clicking.
- **Right click** (`pointerdown` with `button === 2`) on a point (by `hitTest()`) asks for confirmation with `confirm()`, then calls `remove()`, which deletes the point and its lines and shifts higher indices in `lines` and `last` down by one; removing `last` ends the chain. Right click elsewhere sets `last = null`, ending the chain and hiding the preview. The canvas's context menu is disabled.
- **Controls** are fixed at the top-right, over the canvas. Reset clears `points`, `lines` and `last` but leaves the view and the saved copy alone. Save writes `{ points, lines, last, view }` as JSON to `localStorage` under `STORAGE_KEY`; `load()` restores it on startup. Saving is manual only.
- **Lines are drawn as roads** by `roads(c, segs)`, which draws `[p, q]` segments on context `c`: asphalt, white edge lines and a dashed yellow center line. Each layer is drawn for every line before the next layer starts, so roads that cross merge into junctions.
- **Boxes along roads** are generated by `layout()`, not stored or saved. On both sides of each road it places boxes `BOX_MIN`–2×`BOX_MIN` wide with `BOX_GAP` between them, starting `ROAD_WIDTH` from each end, and skips any box that would come near a road, a point or an already placed box. Sizes come from a PRNG (`rng()`) seeded with the road's endpoint coordinates, so the layout is stable. After all boxes are placed, `layout()` puts a tree (`tree()`: round canopy with a highlight and shadow) in the `BOX_GAP` after each placed box, if it is clear of roads, points, boxes and other trees; trees never displace boxes. `layout()` returns `{ boxes, trees }`, and `getScene()` caches it, keyed on `points` and `lines`. `house()` draws each box as a top-down house: a drop shadow, a hip roof with four faces shaded against `LIGHT`, and sometimes a chimney. Roof colour (from `ROOFS`) and chimney come from a PRNG seeded with the box's center, kept separate from the layout PRNG so they don't change box sizes.
- **Rendering is immediate-mode:** `render()` clears and redraws everything (houses, then trees, then roads, then preview, then points on top) from state. It runs on every pointer event and after `resize()`, which is needed because setting `width`/`height` clears the canvas. New visuals should be added to `render()` rather than drawn directly.
